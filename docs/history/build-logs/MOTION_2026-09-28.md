# Expressive motion and power saving — September 28

Direction chosen with the user: expressive motion, with a Power saving mode that turns all of it off. Also delivered: the overlay title bar, bundled fonts, aurora plus grain, glass on floating surfaces, the gradient accent, in-app background-task notifications, and a fix to conversation titles.

## Motion modes

`Settings → Appearance → Motion`, `⌘⇧M`, or the launcher command. The value is stored as `motion` (`expressive` | `saving`) in the settings file and applies immediately. Only that preference is saved; other unsaved Settings edits stay unsaved. Older settings files load as Expressive.

Power saving sets `data-motion="saving"` on the root. `src/lib/motion.ts` makes every Svelte transition and View Transition a no-op, and `app.css` removes CSS animations, transitions, backdrop blur, grain, spotlight, and live-work loops. macOS Reduce Motion has the same effect.

## Moments

- **Send:** your message flies from the composer into the transcript.
- **Live arrivals:** new messages, activity, progress, and thinking rise in. Mounting a conversation, history pages, searches, and restores never animate, so the reading position is unaffected.
- **Live work:**
  - a light band travels along the task header;
  - streaming text has a caret;
  - "working…" shimmers;
  - running commands have a sheen.
    All of these exist only while work runs.
- **Completion:** the check pops and a green sweep crosses the bar. When every observed check passed, sparks burst around the check. It plays once, only for a completion you watched happen.
- **Decisions:** approvals and questions drop in with a spring and pulse once. Question steps slide in the direction of travel.
- **Navigation:**
  - a sliding highlight on primary navigation and the Code/Plan toggle;
  - the composer glow shifts to violet in Plan;
  - views fade up;
  - the theme change is a circular reveal from the pointer;
  - Focus mode glides the side panes out and in.
- **Launcher:** springs in; a single highlight glides between results; results reflow smoothly as you type; a pointer spotlight.
- **History:**
  - rows stagger in and lift on hover, with a spotlight;
  - loading uses shimmering placeholders;
  - the conversation title rises in on switch.
- **Background work:** in-app notifications (Open or dismiss, 7 s); the Tasks button pings and its running count rolls.
- **Detail:**
  - files changed by the agent get a dot that glows once in the tree;
  - folders expand with motion;
  - jumping to a diff change flashes its lines;
  - Copy pops to "Copied ✓";
  - chips pop in and the queued message slides up;
  - dialogs and popovers arrive with a spring.

## Surfaces and identity

- The macOS title bar is merged into the top bar (`titleBarStyle: Overlay`, hidden title, window buttons at 16,18). The bar is a drag region (`core:window:allow-start-dragging`, `core:window:allow-internal-toggle-maximize`).
- Inter and JetBrains Mono variable fonts are bundled offline (`@fontsource-variable/*`).
- A static aurora gradient on the main surface and a static grain overlay.
- Glass on the launcher, dialogs, popovers, notifications, and the jump pill.
- An indigo→violet gradient on primary actions and the logo.

## Conversation title fix

The header previously fell back to the latest user message whenever Codex had not named a conversation. It now uses, in order: the Codex name, the conversation's opening message, then the thread preview. Follow-ups never rename a conversation. The existing regression test was corrected to expect the opening message.

## Measurements (indicative)

Headless Chromium main-thread counters over 6 s during a running task with streaming updates, two runs each:

| Mode         | Main-thread total | Style recalculation |
| ------------ | ----------------- | ------------------- |
| Expressive   | ≈330 ms (≈5.5%)   | ≈50 ms              |
| Power saving | ≈150–225 ms       | ≈8 ms               |

GPU compositing was not measured, and this is not the native WebKit process.

Idle Expressive settles to zero running animations. This is enforced by a test, as is zero animations in Power saving during active work.
